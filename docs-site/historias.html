Historias priorizadas

Las Historias de Usuario se redactaron para reflejar el valor real del negocio: vender mejor, controlar existencias, identificar riesgos operativos y proteger funciones sensibles.

HU-04

Como empleado quiero registrar una venta con varios productos para completar una transacción real de manera ordenada.

Must5 puntos

HU-06

Como administrador quiero registrar entradas de inventario para reflejar la reposición de productos.

Must3 puntos

HU-10

Como sistema quiero bloquear la venta de productos sin stock para evitar inconsistencias de inventario.

Must3 puntos

HU-15

Como sistema quiero identificar productos vencidos para impedir su venta.

Must5 puntos

HU-18

Como administrador quiero ver un resumen de ventas del día para conocer rapidamente el resultado operativo diario.

Must2 puntos

HU-20

Como administrador quiero autenticar usuarios por rol para proteger funciones sensibles del negocio.

Should5 puntos

Criterio de priorizacion

Las `Must` sostienen la operación diaria. Las `Should` agregan control y seguridad. Las `Could` proyectan mejoras de analítica y mayor madurez administrativa.

Relación con Scrum

Las historias guían el backlog, la definición de sprints y la trazabilidad con Casos de Uso, reglas y módulos arquitectonicos.
